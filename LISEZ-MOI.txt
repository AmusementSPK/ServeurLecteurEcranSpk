SPK - SERVEUR HLS ROKU + GESTION WEB
====================================

VERSION DE BASE CONSERVEE
-------------------------
Le système de diffusion n'a pas été remplacé :

MP4 -> FFmpeg -stream_loop -1 -> HLS LIVE -> Roku

Les Roku continuent d'utiliser exactement :
    http://IP_DU_SERVEUR:8090/hls/tv1/index.m3u8
    http://IP_DU_SERVEUR:8090/hls/tv2/index.m3u8
    etc.

La boucle est donc toujours faite par le SERVEUR et non par la télévision.


INTERFACE WEB
-------------
Ouvre :
    http://IP_DU_SERVEUR:8090/

L'interface permet à un employé de :
- voir toutes les télévisions;
- donner un nom clair à chaque TV;
- remplacer sa vidéo avec un bouton;
- voir si le flux FFmpeg est actif;
- copier l'adresse HLS;
- créer une nouvelle TV avec le prochain numéro libre.

Le numéro TV est indépendant de son nom.
Exemple :
    TV 3 = "Menu bar"

La Roku reste configurée comme TV 3 et l'adresse reste :
    /hls/tv3/index.m3u8

Renommer la TV ne casse donc rien.


APPLICATION ROKU : LISTE DYNAMIQUE
----------------------------------
L'application Roku v1.6 ne contient plus de liste TV 1 à TV 8 codée en dur.

Quand le sélecteur est ouvert, elle appelle :
    /api/roku/tvs

Le serveur renvoie les ID et les noms actuels.
Exemple :
    Menu Burgers (TV 1)
    Boissons (TV 2)
    Promotions Entrée (TV 5)

Conséquences :
- créer une nouvelle TV dans le panneau web la rend automatiquement disponible sur Roku;
- renommer une TV change automatiquement son nom dans le sélecteur Roku;
- l'ID reste stable et continue d'identifier l'URL HLS;
- il n'y a plus de limite fixe à 8 TV dans le serveur ou le sélecteur Roku;
- aucun nouveau ZIP Roku n'est requis lorsqu'une TV est ajoutée ou renommée.

Le fichier Roku config/server.env contient seulement l'adresse IP et le port du serveur.


INSTALLATION - SERVEUR PERMANENT
--------------------------------
1. Installer .NET 10 SDK.
2. Lancer 0_INSTALLER_FFMPEG.bat si FFmpeg n'est pas déjà installé.
3. Lancer 1_AUTORISER_PARE_FEU.bat comme administrateur.
4. Faire CLIC DROIT > Executer en tant qu'administrateur sur :
       4_INSTALLER_DEMARRAGE_AUTO.bat
5. Ouvrir : http://localhost:8090/

Le serveur est ensuite lancé sous le compte SYSTEM au démarrage de Windows.
Aucune session utilisateur n'a besoin d'être ouverte.

Protection automatique :
- FFmpeg arrêté/crashé : relance automatique par le serveur;
- erreur dans la boucle HLS : isolée pour ne pas faire tomber le serveur web;
- serveur .NET crashé : relance par SPK_Server_Watchdog.ps1;
- serveur figé / health invalide : arrêt forcé après 3 contrôles ratés puis relance;
- watchdog arrêté : le Planificateur Windows tente de le relancer;
- redémarrage Windows : démarrage automatique;
- double lancement : bloqué par mutex + règle IgnoreNew;
- logs conservés dans Logs/ (rotation des logs serveur après 30 jours).

3_DEMARRER_SERVEUR.bat reste disponible uniquement pour les tests/maintenance.
6_ETAT_SERVEUR.bat affiche l'état de la tâche Windows et de /health.
5_DESINSTALLER_DEMARRAGE_AUTO.bat retire le démarrage automatique.


CONFIGURATION DES TV
--------------------
Au premier démarrage, le serveur crée automatiquement :
    Data/tvs.json

à partir de la section Streaming:Tvs de appsettings.json.

Après ce premier démarrage, l'interface web gère Data/tvs.json.
Le fichier est volontairement ignoré par Git pour ne pas écraser les noms des TV lors d'un pull.

Il n'y a plus de limite MaxTvCount arbitraire. Les numéros sont attribués automatiquement avec le prochain ID libre.


CHANGER UNE VIDEO
-----------------
Dans l'interface :
1. Choisir le fichier MP4.
2. Cliquer "Remplacer la vidéo".
3. Le serveur arrête seulement le FFmpeg de cette TV.
4. Il remplace le MP4.
5. Il redémarre automatiquement le même flux HLS.

La Roku conserve donc la même URL.

Format recommandé :
- MP4
- H.264 / AVC
- AAC si audio
- 1080p ou 4K selon la TV


IMPORTANT POUR GIT
------------------
Les dossiers/fichiers suivants ne doivent pas être versionnés :
- bin/
- obj/
- Hls/*
- Media/*.mp4
- Data/tvs.json

Ils sont couverts par .gitignore.
